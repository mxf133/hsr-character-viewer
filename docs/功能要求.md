## 2. 术语

| 术语 | 含义（当前口径） |
| --- | --- |
| **整包** | 角色 + 星魂档 + 光锥（含叠影）三元组。内部字段仍叫 `pack`/`packs` |
| **配队 / 队伍** | 四名成员的整包组合。界面上一律叫「配队」（用户的读法） |
| **成本 N 金** | 该**整包**的账面金数：本体 1 + 星魂级数 + 光锥本体 × 叠影（限定才算钱；4★/常驻 0 金）。**不含**隐金减免 |
| **补金 N 金** | 从「你现在有什么」到「照抄这套」还要抽几发。与「成本」是两个数 |
| **隐金减免** | 只用于展示（「这些单位不用抽，账面扣掉 N 金」），不参与差额计算 |
| **原始量** | 某个分项在**它自己的量纲**下的累计值 —— **没做榜内归一、也没乘权重**，就是角色得分详情窗口分项表里「原始量」那一列。三个分项量纲完全不同，见 §6.3 |
| **得分** | 原始量换算到 **0~100** 之后的值（分项表「得分」列）。强度：绝对刻度（不经 min-max，但要过包络 / 天花板）；性价比：**先开平方、再榜内** min-max（v4.6.119，`SCORING.costScorePower = 0.5`）；泛用性：**按组各一把尺子**的 min-max（见 §5） |
| **贡献** | `得分 × 该分项的抽卡权重`（分项表「贡献」列）。三行贡献相加 = **角色得分**（合计行逐字等于徽标上那个数） |
| **角色强度 / 角色性价比 / 角色泛用性** | **角色总榜**那三个分项的名字（✅ v4.6.115 由「强度 / 性价比 / 泛用性」改，用户 2026-10-17 第 2 条）。角色得分的公式与旧名**逐字相同**，只是分项名带上了「角色」二字 |
| **队伍强度 / 队伍性价比 / 队伍泛用性** | **抽卡方案（补金推荐）**那三个分项的名字（✅ v4.6.115 由「强度得分 / 性价比 / 泛用性」改，用户 2026-10-17 第 4 条）。旧名「**强度得分**」作废 |
| **抽卡权重（输入框）** | 那三个**输入框**仍叫「**强度 / 性价比 / 泛用性**」，**不带**「角色 / 队伍」前缀 —— 它们是两个榜**共用**的一组系数（用户 2026-10-17 确认，见 §9 第 9 条） |

## 3. 三类权重（互不相同、各自独立、都只有一份来源）

### 3.1 关卡权重（5 个副本）

* 默认 **绝境 5 / 其余四个各 1**（`SCORING.envWeight`；2026-10-14 由 10 降到 5）。
* 决定「哪些副本算数」，总榜与抽卡方案**共用同一套**。
* 0 是有效值（该副本不参与），恢复默认回到上表。

### 3.2 抽卡权重（强度 / 性价比 / 泛用性）

* **默认 4 : 5 : 1** ✅ 2026-10-18 由 `1 : 1 : 0.5` 改（`SCORING.drawWeight`）。
* 三键都**只认相对大小**，由 `normalizeDrawWeights()` 归一到和为 1 → 默认 **0.4 / 0.5 / 0.1**
  （强度 40% / 性价比 50% / 泛用性 10%）。
* **两个榜共用同一个归一结果**：角色总榜的「角色得分」与抽卡方案的「补金推荐分」都是
  `强度 × ws + 性价比 × wc + 泛用性 × wv`，所以「强度 3 / 性价比 1 / 泛用性 1」在两边都是 `0.6 / 0.2 / 0.2`。
* 边界（`drawWeightValues` / `normalizeDrawWeights`）：

  | 输入 | 结果 |
  | --- | --- |
  | 不传 / 缺键 / `null` | 按**默认值**补齐（4 / 5 / 1） |
  | 空串（用户清空输入框） | 按 **0** 算 |
  | 负数 / `NaN` / 非数字 | 忽略，退回默认 |
  | 三项全 0 | 退回**默认比例**（不是让分数塌成 0） |

* 「恢复默认」按钮 = 回到 `4 / 5 / 1`（摘要印 `强度 40% · 性价比 50% · 泛用性 10%`）。
* ⚠️ 老用户的 localStorage 存档**优先于**默认值：改默认不会改掉已存过的 `{1,1,1}`。
* ⚠️ **输入框标签不含「角色 / 队伍」前缀**（用户 2026-10-17 确认）：这三个框是**两个榜共用**
  的一组系数，加前缀会被读成「只管某一个榜」。两个榜各自的**分项名**才带前缀 ——
  角色总榜叫「角色强度 / 角色性价比 / 角色泛用性」、抽卡方案叫「队伍强度 / 队伍性价比 /
  队伍泛用性」。三处（输入框 / 两个榜的分项）的**顺序恒为 强度 → 性价比 → 泛用性**。

### 3.3 版本权重（默认 6 槽位，可增删到 1~12）

* 默认 **6 : 5 : 4 : 3 : 2 : 1**（`VERSION_WEIGHTS`），默认窗口 6 版。
  ⚠️ 2026-10-18 由 `3 : 2.5 : 2 : 1.5 : 1 : 0.5` 改 —— 新表**逐项 = 旧表 × 2**，
  而版本权重只以「分子分母同除同一个和」的加权平均出现，所以**分数与名次都不变**，
  这一改只把刻度换成整数（脚注不再印 `2.5`）。
* **槽位可增删（用户 2026-10-17）**：「版本权重」小标题右边两个按钮 ——
  **加一版**（末尾补一档，默认沿用最后一档 **1**，不归零）、
  **删一版**（去掉最后一档）。
  上限 `VERSION_WEIGHT_MAX` = **12**（本地数据集最长的副本 15 版、其余 10~13 版，
  再多没有数据支撑），下限 **1**；按钮到界时 `disabled`，处理器里另有一道 return。
  ⚠️ 档位数**就是**窗口长度：服务端两条链（`archiveFrontier` 与 `resolveScope`）的窗口
  跟着表长走，所以加一档 = 真的把更旧的那一版拉进加权。
* 槽位**按下标**、**不绑定版本号**（黑塔网加一版整表前移）；**每个副本各有一套版本号**
  （4.5 在混沌与异相仲裁里不是同一期）。
* **文案（v4.6.114 改）**：槽位名是 **「当前版本」「前1个版本」「前2个版本」…**；
  原「最新版 / −1 版 / −2 版 …」不再使用。第 7 档起是「前6个版本」「前7个版本」…
* **不做「归一到 1」**：界面印的是**比值串**（`当前版本 6 : 前1个版本 5 : …`），不印百分比；
  摘要行还印出当前的**版数**（`每个副本各自算（6 版）：…`）。
* 某版设 **0 = 那一版不进窗口**；全部设 0 → 退回默认表（**档位数保留**）。
* **存档形状**：数组（界面自己写的）→ **长度就是档位数**（「删一版」就是存短数组）；
  对象（`{'0':3}` 这种老形状，界面从没写过它）→ 至少补到 6 档再按默认补齐。
* 生效范围：服务端按它现算每个副本的 `seasonWeights`，客户端再做跨版本加权 —— 所以改它要**重算结论**。

## 4. 强度得分（角色总榜的 ① / 抽卡方案的 ①）

> 2026-10-17 **晚**改定：**强度只看行动值**（用户原话「强度得分应仅考虑强度（不考虑别的，
> 因此低难副本普遍能拿满分）」）。当天上午那版还按金数折分（顶格档 `100 × 最省金 ÷ 本队金数`、
> 第二档封顶 `min(90, 100 × 最省 ÷ 最贵)`），实测把 18 金的 E6 队在「1 金就能 0 行动值」的
> 混沌 / 虚构里压到个位数 —— 强度列读出来的是「贵不贵」而不是「快不快」，已整条删除。
> 成本的事只归「性价比」那一项（§6.3）。

### 4.1 单版本的两档（五个副本同一套）

```
该版本该关卡的强度 = a == 0 → 100
                     否则   → 95 × 判据线曲线(a)
```

* **单位口径**（`avUnitOf`）：绝境王棋关 = **行动值**；末日幻影 = **积分**（内部
  `a = 4000 − 积分`）；混沌回忆 / 虚构叙事 / 异相仲裁普通关 = **轮次**。
  `a === 0` 在五个副本里都表示「最好成绩」。
* **金数不参与**：改前顶格档是 `100 × 该期最省金 ÷ 本队金数`、第二档封顶是
  `min(90, 100 × 最省 ÷ 最贵)`，两处都在按成本折分 —— 已删除；`zeroAvGoldBySeason`
  这个字段**不再被强度读取**（仍随载荷下发，供探针复算历史口径）。
* **低难副本会普遍拿满分**：混沌 / 虚构 / 异相普通关的最省 0 行动值队只要 1~3 金，
  任何打出 0 行动值的配置都拿 100。用户明确接受这一点（「仅考虑强度」的直接结果）。
* **非顶格档封顶 95**（用户 2026-10-18 第 2 条，**逐关卡**生效）：没打出 0 行动值的队
  再好也够不到顶格那一档。这条只由行动值决定，与成本无关。
  改前它还在**整包层**再夹一刀（`min(合计, 90)`），2026-10-18 已删 —— 见 §4.4。
* 曲线锚点：0 行动值 = 1.00、判据线 0.80 / 达标线 0.45 / 及格线 0.20（`strengthLineWeights`）。
  ⚠️ 它与**性价比**那条曲线不是同一把尺子（那条在绝境满分线以内是平的 1.00）。

### 4.2 强度只看最快的 + 环境级继承（已登场却无证据）

```
该副本强度 = 窗口内所有自己的证据行里**最强的那一行**（按两档规则算）
```

* **强度只看最快的**（2026-10-18 第 1 条）：不再按版本权重做加权平均 ——
  某一期打出 0 行动值，那一关就是 100；不能拿没发挥好的期数去稀释最好成绩。
  ⚠️ **版本权重从此只影响性价比与泛用性**，不再影响强度。
* **早于登场** → 没有那一期的证据，自然不参与「最快」的比较。
* **环境级继承**（2026-10-18，用户原话：「如果已登场却无证据，一个高成本角色自动继承
  其低成本角色的得分，因为人们一般不会上传低难度关卡用超高成本通关的记录，**这种情况下，
  分母要算所有副本的权重**」）：
  * 某个副本这一档**一条自己的投稿都没有** → 在同一副本的**更便宜同角色整包**里取最高
    强度，作为这一关的强度（那一关**仍然留在分母 9 里**，借来的分进分子）；
  * 只从「自己有实测证据」的整包继承，**不做链式传递**；
  * 成本**相等**不算更便宜（E2+限定S4 与 E6+免费S0 可能都是 7 金，互不继承）；
  * 「更便宜」按**原始整包金数**（隐金前）比较；
  * **只借同一副本**的成绩（池子逐副本建），绝不跨副本平移；
  * 继承来的分**只进强度列**，不进性价比、不进泛用性（那两个分项照旧）。
* **继承不到**（同角色没有任何更便宜的整包打过这一关）→ 这一关按 0 计，
  权重照进分母（§4.3 的「缺副本按 0」）。
* 界面在继承那一格的行动值处写「继承」，不印出借方的行动值（避免读成自己打出来的）。

### 4.3 整包合计（缺副本按 0，环境级继承之后只剩「真正没投稿的关」）

```
强度原始量 = Σ(关卡权重 × 该副本强度) / Σ(**全部**副本的关卡权重)     ← 缺副本按 0
```

* 5 个副本的关卡权重是 **绝境 5 + 其余各 1 = 9**。一个整包在某个副本**既没有自己的投稿、
  也借不到更便宜同角色的分**时，分子加 0，**分母仍然算上那个副本的权重**。
* ⚠️ 2026-10-18 加了环境级继承之后，「缺副本按 0」只剩两种情况：
  * 同角色**根本没有更便宜的整包**（本来就是最低配）；或
  * 更便宜的整包**也没打过这一关**。
  其余情况都靠继承把这一关填上，所以「覆盖 2/5」不再必然把上限压到 66.7。
* 为什么分母仍算全部副本：把「没有投稿」当成「没打出过」（明确的差），而不是「未知」。
  改前试过「只除以有数据的副本」，结果**投稿越少分越高** —— 实测总榜每角色留一条时
  专挑数据最少的整包，绝境覆盖率从 36/77 掉到 1/77，强度榜直接失真。
### 4.4 强度分（整维不再夹天花板，2026-10-18）

```
强度分 = 本档自己的 强度原始量
         （本档在**每一个有数据的关卡**都打出过 0 行动值时 = 100）
```

> 只看最快之后，100 的门槛从「每关**每期**都 0 行动值」降到「每关**至少有一期**
> 0 行动值」。2026-10-18 实测 81 条整包里 **8 条**达到 100（改前 0 条）。

* **单调包络已整条删除**（2026-10-17 第 2 条）：改前它会「用同角色更低档位的成绩救
  更高档位」，实测真珠 E0/E1/E2/E6 四档强度分**全部等于 73.33**，强度列读不出任何档位
  差异。现在每一档就是它自己（含继承）的成绩。
* **整维 90 天花板也已删除**（2026-10-18，用户报「只考虑强度时前排角色普遍不够强」）：
  那一刀把 90.3~95.2 的原始分全压成并列 90.0，名次退化成按性价比兜底键排。
  「没打出 0 行动值就够不到顶格」这条规则**已经由逐关卡的 95 上限实现**：只要有一关
  不是 0 行动值，那一关最多 95。
* **第二档上限从 90 改到 95**（用户 2026-10-18 第 2 条）：非 0 行动值最高 95 分，
  与顶格档（100）留 5 分空档。
* 绝对刻度 0~100，**不做榜内归一**。
* ⚠️ **整包 100 极难出现**：要 5 个副本 × 窗口内每一期都打出 0 行动值才算。当前数据集
  实测 **0 条**。这是结构性的，不是 bug —— 「每一关都能拿满分」说的是**单关**。
* 成本（星魂 / 叠影 / 光锥）只影响「性价比」那一项，**不影响强度**
  （用户 2026-10-17 第 2 条「删除，强度只看行动值/通关情况」）。
  ⚠️ 唯一的例外是 §4.2 的**继承**：缺证据时高成本档会借低成本档的分，
  这是用户当轮点名要的方向，不是成本加成。

### 4.5 「行动值前沿」候选池（只服务抽卡推荐）

* 服务端每副本发该副本行动值最好的 8 支（逐版本按**权重最高的有数据版本**取代表行）。
* 池内 ① 用**本队自己的行动值**按同一条两档规则折算，加权分母 =
  「本队有数据的关卡」+「**缺关卡里比本队打过的任何一关都更重**的那些」（v4.6.112）。
* 不参与单调包络。
* **每支队伍都要有来源视频** ✅ v4.6.115（用户 2026-10-17 第 5 条「提供抽卡方案-所有队伍的
  视频链接（类似角色总榜）」）。这一池原先**恒为 `null`**：建库侧的前沿行只有 `{c,a,t,m}`
  四个键、本来就没有投稿地址，而它恰恰是「0 行动值满配队」的唯一来源 ——
  于是抽卡方案**前排全是点不出视频的卡片**（改前实测 15 张卡只有 7 张有）。
  修法：服务端按 `版本|阵容` 回查 `teams[].sample.video`（`archive.js` 的
  `sampleVideoByRosterSeason`，口径与 `archiveFrontier` 逐字相同），
  **跟着 `avRowFor` 挑中的那一版走**，查不到就如实留空。实测 5 个副本 × 8 条 = **40/40**。

## 5. 泛用性

> 2026-10-17 第 1 条**整节重做**：「E6 角色应当仅与 E6 做比较，E0/E1/E2 与 E0/E1/E2
> 之间做比较（避免不同量级之间的比较）」。E6 出现在更少的投稿里 ⇒ 原始量系统性偏低，
> 混在一把尺子上比就是拿量纲不同两个数比大小。
>
> ✅ **2026-10-17 修复（本分支 `fix/versatility-algorithm`，用户拍板「分位夹逼 + 缺副本口径」）**：
> 原口径的两处结构性缺陷 —— ① 尺子是裸 min-max，被单个离群值撑满（榜面 180 条里
> 126 条 ≤10 分、中位 3.8、90 分以上只有 3 条）；② 跨副本分母用的是**全部副本**的
> 权重和，让「投稿覆盖了几个副本」直接决定分数被除几（原始量中位：1 个副本 0.169 →
> 5 个副本 1.044）。修法见下面带 ✅ 的两条。

* **两把尺子，各归一各的**：
  * **低档组**（E0/E1/E2）：原始量 = 该角色在三档上**各按档平均**、再**对三档平均**；
  * **E6 组**：原始量 = 该角色 **E6 那一档**的平均。
  * 两组各自归一 到 0~100（`versatilityExtentOfGroup('low'|'e6')`）。
  * ✅ **尺子是 p5 ~ p95，不是裸 min-max**：两端各裁 `SCORING.versatilityExtentTrim`
    （0.05）的分位当端点，超出区间由 `clamp(0, 1)` 夹到 0 / 100。样本数 <
    `versatilityExtentTrimMinSamples`（20，测试夹具 / 合成数据）时退回 min/max ——
    三五个点谈分位没有统计意义。取样**按角色去重**（同一角色同组的所有整包带同一个
    原始量，不去重等于给「配装多的角色」重复计票）。
  * 实测（修前 → 修后）：低档组榜面中位 **3.8 → 4.1**、p90 **30.8 → 60.3**、
    90 分以上 **3 条 → 9 条**；E6 组中位 **2.0 → 7.7**、p90 **30.4 → 56.1**。
    原始量本身也整体上移（低档组中位 0.51 → 1.67），因为下面那条分母修正。
* **同一个角色可能有两份原始量**（一份低档、一份 E6），界面上按**这一行自己的星魂档**
  取对应那一份；`frontierExtents.versatility` 的 `lo/hi` 是低档组、`byTier[6]` 是 E6 组。
* 双重加权：副本内按**版本权重**、跨副本按**关卡权重**。
  * 缺**投稿版本**按 **0** 计（与强度同一条两态规则：已登场却没有任何成绩 = 明确的差）。
  * ✅ 缺**副本**不再按 0 计：跨副本那一步的分母是**这个整包有数据的那些副本**的权重和。
    理由是强度量成绩（没成绩确实是差），泛用性量关系网（没投稿 ≠ 不百搭），照抄会
    把「没人投稿」读成「不百搭」。实测原始量中位随「有数据副本数」的爬升从
    **6.2 倍缩到 3.0 倍**（剩余部分是真实差异：投稿覆盖广的角色确实更百搭）。
  * 关卡权重仍在分子里生效 —— 「不能因为某角色在低权重关卡泛用就当成高权重关卡也泛用」
    这条（2026-10-16 第 4 条）没有被削弱。
* 分子分母**都不含「不用抽就有」的角色**（常驻 5★ / 开拓者任意命途 / 大隐金）。
* **队级**（抽卡方案）＝ 每个成员**先按自己那一组**归一成组内相对分，再按**成员金数占比**
  加权；队伍总金 0 时退回等权平均。
  恒等式：**队级 ③ = 成员们在总榜上泛用性分的成本加权平均**。
* 归一是 **p5~p95 夹逼**，但**不再是「榜内」**：角色级用上面那两把组尺子；队级优先读
  同一份 `frontierExtents`（恒等式成立），取不到时按候选池现算，**同一个
  `versatilityExtentOf`**（顺手修了旧兜底没跳过「不用抽就有」角色、lo 被拉到 0 的分叉）。
* 泛用性权重**也适用于补金推荐**（用户 2026-10-13 第 3 条），即三键在方案里一并归一。
* ⚠️ **仍然是已知特性**：低档组的「三档平均」会把 E1/E2 的稀疏惩罚摊进来 —— 实测
  `原始量 ÷ E0 本档值` 的中位只有 **0.59**（p25 0.46 / p90 1.31），因为 E1/E2 的投稿
  本来就少。这是用户 2026-10-16 第 3 条定的口径（`docs` 本节上一轮），本分支
  **没有动**（用户明确「三档平均保留」）。要改成「按证据条数加权」得另开决策。

### 6.3 「原始量 → 得分 → 贡献」这条链（每个分项各自不同）

分项表就四步：**原始量**（自己量纲的累计值）→ **得分**（换到 0~100）→ **权重**（抽卡权重）
→ **贡献**（`得分 × 权重`），三行贡献相加 = 角色得分。三个分项的换算方式**不一样**，
这正是必须把「原始量」摆出来、并写出榜内区间的原因（否则读者按 min-max 去验算强度，
永远对不上）：

| 分项 | 原始量是什么 | 量纲 | 原始量 → 得分 |
| --- | --- | --- | --- |
| **强度** | `strengthTotal` = Σ(关卡权重 × 该关强度) / Σ(**全部**副本权重)，缺副本按 0（**已登场却缺证据**先继承更便宜整包的成绩，继承不到才按 0）。该关强度按 §4.1 两档规则逐关算 | 0~100 的分（绝对刻度） | **不 min-max**：得分 = 包络 / 天花板之后的那个原始量。⚠️ **v4.6.119 起金数彻底退出**：`0 行动值 → 100`、其余 `95 × 曲线`；改前是「顶格档 = `100 × 本期最省金 ÷ 本队金数`、非顶格档封顶 90」，见 §9 第 24 行 |
| **性价比** | `total` = Σ(关卡权重 × 该关的整包分) **× 整包系数**，其中该关的整包分 = `100 × 表现 × 金数项`。⚠️ **2026-10-17 起是配装口径**（用户「走 A + D」）：多了 `整包系数 = (该角色榜上最便宜的整包金数 ÷ 本整包金数) ^ SCORING.ownGoldFactorPower`，指数 **v4.6.119 起是 1.0**（改前 0.5）。分母分子都用**隐金前**的金数（`ownGold`）。改前只有队伍金数、整包自己花多少金完全不进公式（实测 `r(整包金数, 性价比得分) = 0.030`） | 分数（与强度不是一个量纲），实测跨度 1623 倍 | 得分 = `100 × (原始量^0.5 − 榜内最小) / (榜内最大 − 榜内最小)`，区间取**全榜**（端点也在**开平方之后**的刻度上），`power` 由 `frontierExtents.cost.power` 下发。⚠️ 因为系数只乘在整包层面，界面**必须**在性价比来源表标题行印出「× 整包系数 N（最便宜 X 金 ÷ 本整包 Y 金）」，分母用 `ownGold`（隐金前），否则 `Σ逐关卡贡献 × 系数 = 合计` 这条验算链会断 |
| **泛用性** | 加权的**不同队友数**（副本内按版本权重、跨副本按**有数据的副本**的关卡权重；缺投稿版本计 0，缺副本**不**按 0，见 §5）。✅ 2026-10-17 修复前缺副本也按 0，等于把「没人投稿」读成「不百搭」 | **个数**（小数，实测缇宝 **4.21** 个；修复前是 1.88，差额来自分母修正） | **p5~p95 夹逼**，尺子**按组各一把**（2026-10-17 第 1 条）：低档组（E0/E1/E2 三档平均）与 E6 组各自一对端点，得分 = 100 ×（原始量 − p5）/（p95 − p5），超出夹到 0 / 100。修复前是裸 min-max（被离群值撑满：榜面 180 条里 126 条 ≤10 分）。为 0 的两种来源：① 该角色本身是「不用抽就有」的那批 → **既不攒自己的集合、也不当别人的队友**（实测希儿 / 镜流 / 银狼 = 0）；② 它的队伍里除自己外全是这类角色 |

📌 一句话：**原始量是"算分之前那个数"，得分是"换算到 0~100 之后的数"，贡献是"这个分项最终给角色得分加了多少"**。
界面上那一列下还会写 `（榜内 0.2 ~ 644.2）`、`（组内 5%~95% 分位 0.7 ~ 7.2）` 或
`（绝对刻度 0~100）`，就是为了让读者能自己验算。**泛用性那一格 2026-10-17 起不能写「榜内」**
—— 它的两个端点已经是 p5/p95，不是全榜最小 / 最大（照旧写会让人验算出 >100 的分）。

（上表那三个分项名在**详情窗口**里显示为「角色强度 / 角色性价比 / 角色泛用性」，
在**总榜筛选器上方**那三个输入框里仍显示为「强度 / 性价比 / 泛用性」—— 见 §3.2 那条 ⚠️。）

## 7. 文案总则（有源码级 / 全窗口判据）
