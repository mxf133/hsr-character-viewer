## 2. 术语

| 术语 | 含义（当前口径） |
| --- | --- |
| **整包** | 角色 + 星魂档 + 光锥（含叠影）三元组。内部字段仍叫 `pack`/`packs` |
| **配队 / 队伍** | 四名成员的整包组合。界面上一律叫「配队」（用户的读法） |
| **成本 N 金** | 该**整包**的账面金数：本体 1 + 星魂级数 + 光锥本体 × 叠影（限定才算钱；4★/常驻 0 金）。**不含**隐金减免 |
| **补金 N 金** | 从「你现在有什么」到「照抄这套」还要抽几发。与「成本」是两个数 |
| **隐金减免** | 只用于展示（「这些单位不用抽，账面扣掉 N 金」），不参与差额计算 |
| **原始量** | 某个分项在**它自己的量纲**下的累计值 —— **没做榜内归一、也没乘权重**，就是角色得分详情窗口分项表里「原始量」那一列。三个分项量纲完全不同，见 §6.3 |
| **得分** | 原始量换算到 **0~100** 之后的值（分项表「得分」列）。强度：绝对刻度（不经 min-max，但要过包络 / 天花板）；性价比：**榜内** min-max；泛用性：**按组各一把尺子**的 min-max（见 §5） |
| **贡献** | `得分 × 该分项的抽卡权重`（分项表「贡献」列）。三行贡献相加 = **角色得分**（合计行逐字等于徽标上那个数） |
| **角色强度 / 角色性价比 / 角色泛用性** | **角色总榜**那三个分项的名字（✅ v4.6.115 由「强度 / 性价比 / 泛用性」改，用户 2026-10-17 第 2 条）。角色得分的公式与旧名**逐字相同**，只是分项名带上了「角色」二字 |
| **队伍强度 / 队伍性价比 / 队伍泛用性** | **抽卡方案（补金推荐）**那三个分项的名字（✅ v4.6.115 由「强度得分 / 性价比 / 泛用性」改，用户 2026-10-17 第 4 条）。旧名「**强度得分**」作废 |
| **抽卡权重（输入框）** | 那三个**输入框**仍叫「**强度 / 性价比 / 泛用性**」，**不带**「角色 / 队伍」前缀 —— 它们是两个榜**共用**的一组系数（用户 2026-10-17 确认，见 §9 第 9 条） |

## 3. 三类权重（互不相同、各自独立、都只有一份来源）

### 3.1 关卡权重（5 个副本）

* 默认 **绝境 5 / 其余四个各 1**（`SCORING.envWeight`；2026-10-14 由 10 降到 5）。
* 决定「哪些副本算数」，总榜与抽卡方案**共用同一套**。
* 0 是有效值（该副本不参与），恢复默认回到上表。

### 3.2 抽卡权重（强度 / 性价比 / 泛用性）

* **默认 1 : 1 : 0.5** ✅ v4.6.114 由 `1 : 1 : 1` 改（`SCORING.drawWeight`）。
* 三键都**只认相对大小**，由 `normalizeDrawWeights()` 归一到和为 1 → 默认 **0.4 / 0.4 / 0.2**。
* **两个榜共用同一个归一结果**：角色总榜的「角色得分」与抽卡方案的「补金推荐分」都是
  `强度 × ws + 性价比 × wc + 泛用性 × wv`，所以「强度 3 / 性价比 1 / 泛用性 1」在两边都是 `0.6 / 0.2 / 0.2`。
* 边界（`drawWeightValues` / `normalizeDrawWeights`）：

  | 输入 | 结果 |
  | --- | --- |
  | 不传 / 缺键 / `null` | 按**默认值**补齐（1 / 1 / 0.5） |
  | 空串（用户清空输入框） | 按 **0** 算 |
  | 负数 / `NaN` / 非数字 | 忽略，退回默认 |
  | 三项全 0 | 退回**默认比例**（不是让分数塌成 0） |

* 「恢复默认」按钮 = 回到 `1 / 1 / 0.5`。
* ⚠️ 老用户的 localStorage 存档**优先于**默认值：改默认不会改掉已存过的 `{1,1,1}`。
* ⚠️ **输入框标签不含「角色 / 队伍」前缀**（用户 2026-10-17 确认）：这三个框是**两个榜共用**
  的一组系数，加前缀会被读成「只管某一个榜」。两个榜各自的**分项名**才带前缀 ——
  角色总榜叫「角色强度 / 角色性价比 / 角色泛用性」、抽卡方案叫「队伍强度 / 队伍性价比 /
  队伍泛用性」。三处（输入框 / 两个榜的分项）的**顺序恒为 强度 → 性价比 → 泛用性**。

### 3.3 版本权重（6 槽位）

* 默认 **3 : 2.5 : 2 : 1.5 : 1 : 0.5**（`VERSION_WEIGHTS`），窗口 6 版。
* 槽位**按下标**、**不绑定版本号**（黑塔网加一版整表前移）；**每个副本各有一套版本号**
  （4.5 在混沌与异相仲裁里不是同一期）。
* **文案（v4.6.114 改）**：槽位名是 **「当前版本」「前1个版本」「前2个版本」…「前5个版本」**；
  原「最新版 / −1 版 / −2 版 …」不再使用。
* **不做「归一到 1」**：界面印的是**比值串**（`当前版本 3 : 前1个版本 2.5 : …`），不印百分比。
* 某版设 **0 = 那一版不进窗口**；六项全 0 → 退回默认表。
* 生效范围：服务端按它现算每个副本的 `seasonWeights`，客户端再做跨版本加权 —— 所以改它要**重算结论**。

## 4. 强度得分（角色总榜的 ① / 抽卡方案的 ①）

> 2026-10-17 第 2、3 条**整节重做**。旧口径是「行动值 + 投入加成」的合成
> （`95 × 包络 + 5 × 第二维`），同一个 0 行动值的配装花 48 金与花 12 金能同分 ——
> 用户判「高造价必然等于高强度」不成立，要求强度与成本脱钩、只看行动值 / 通关情况。

### 4.1 逐关卡两档（五个副本同一套）

```
该关卡强度 = 这一期有人打出 a == 0（顶格档） → 100 × 本期最省金 ÷ 本队金数
             没人打出 a == 0（非顶格档）     → min(90, 90 × 判据线曲线(a))
```

* **单位口径**（`avUnitOf`）：绝境王棋关 = **行动值**；末日幻影 = **积分**（内部
  `a = 4000 − 积分`）；混沌回忆 / 虚构叙事 / 异相仲裁普通关 = **轮次**。
  `a === 0` 在五个副本里都表示「最好成绩」。
* **顶格档**：`a === 0` 的判定与「本期最省金」都**按版本各算**（服务端
  `zeroAvGoldBySeason`），**不跨版本比较**；跨版本累加时按用户设的版本权重加权。
  所以「最省金那支 = 100」是**每一期各自**的 100。
* **非顶格档**：沿用判据线曲线（锚点 0 = 1.00 / 判据线 0.80 / 达标线 0.45 /
  及格线 0.20，`strengthLineWeights`），**封顶 90**。
  用户确认：90 是「必须低于 100」的**同一层**，不是额外一档；
  「48 金也达不成 0 行动值」与「需要更多金才达成」的先后关系也由这两档自然表达
  （前者整档压在 90 以下，后者按 `最省金 ÷ 本队金数` 等比降）。
* 曲线锚点：0 行动值 = 1.00、判据线 0.80 / 达标线 0.45 / 及格线 0.20（`strengthLineWeights）。

### 4.2 整包合计

```
强度原始量 = Σ(关卡权重 × 该关强度) / Σ(**全部**副本的关卡权重)     ← 缺副本按 0
```

### 4.3 单调包络 + 天花板

* 包络：取「同角色、星魂 ≤、叠影 ≤」的整包里的**前缀最大**，且**至少一维严格更低**才兜底
  （档位相同时不互相兜底 —— 否则「不装光锥」会白捡「装了免费锥」的成绩）。
* **天花板按档各自生效**：每一档先看**它自己**是不是顶格档；
  非顶格档的整包加权分封顶 90，**顶格档不压**（旧口径是「第二档天花板对整维统一生效」，
  会把顶格档也压到 90 —— 已随本节重做一并作废）。
* 投入**只按金算**：免费 / 4★ 光锥的叠影不花一抽，**不算**叠影档；E3~E5 折进 E2。
* 绝对刻度 0~100，**不做榜内归一**。
* 用户点名的不变式：抽样角色的可比档位里「投入更高时强度从不更低」（`strength-invariant-test`）。
  ⚠️ 它只在**非顶格档内**严格成立（顶格档按 `最省金 ÷ 本队金数`，是用户 2026-10-16
  第 1 条明确选的取舍；当前数据集里没有顶格档整包）。

### 4.4 强度分

```
强度分 = 强度原始量（封顶 / 包络之后）
```

* 旧口径那 `+ 5 × 第二维`（压金度 / 投入档位）**已删除** —— 强度只看行动值 / 通关情况，
  成本的事归「性价比」那一项（用户 2026-10-17 第 2 条「删除，强度只看行动值/通关情况」）。

### 4.5 「行动值前沿」候选池（只服务抽卡推荐）

* 服务端每副本发该副本行动值最好的 8 支（逐版本按**权重最高的有数据版本**取代表行）。
* 池内 ① 用**本队自己的行动值**按同一条两档规则折算，加权分母 =
  「本队有数据的关卡」+「**缺关卡里比本队打过的任何一关都更重**的那些」（v4.6.112）。
* 不参与单调包络。
* **每支队伍都要有来源视频** ✅ v4.6.115（用户 2026-10-17 第 5 条「提供抽卡方案-所有队伍的
  视频链接（类似角色总榜）」）。这一池原先**恒为 `null`**：建库侧的前沿行只有 `{c,a,t,m}`
  四个键、本来就没有投稿地址，而它恰恰是「0 行动值满配队」的唯一来源 ——
  于是抽卡方案**前排全是点不出视频的卡片**（改前实测 15 张卡只有 7 张有）。
  修法：服务端按 `版本|阵容` 回查 `teams[].sample.video`（`archive.js` 的
  `sampleVideoByRosterSeason`，口径与 `archiveFrontier` 逐字相同），
  **跟着 `avRowFor` 挑中的那一版走**，查不到就如实留空。实测 5 个副本 × 8 条 = **40/40**。

## 5. 泛用性

> 2026-10-17 第 1 条**整节重做**：「E6 角色应当仅与 E6 做比较，E0/E1/E2 与 E0/E1/E2
> 之间做比较（避免不同量级之间的比较）」。E6 出现在更少的投稿里 ⇒ 原始量系统性偏低，
> 混在一把尺子上比就是拿量纲不同两个数比大小。

* **两把尺子，各归一各的**：
  * **低档组**（E0/E1/E2）：原始量 = 该角色在三档上**各按档平均**、再**对三档平均**；
  * **E6 组**：原始量 = 该角色 **E6 那一档**的平均。
  * 两组各自 min-max 到 0~100（`versatilityExtentOfGroup('low'|'e6')`）。
* **同一个角色可能有两份原始量**（一份低档、一份 E6），界面上按**这一行自己的星魂档**
  取对应那一份；`frontierExtents.versatility` 的 `lo/hi` 是低档组、`byTier[6]` 是 E6 组。
* 双重加权：副本内按**版本权重**、跨副本按**关卡权重**；缺投稿版本 / 缺副本都按 **0** 计。
* 分子分母**都不含「不用抽就有」的角色**（常驻 5★ / 开拓者任意命途 / 大隐金）。
* **队级**（抽卡方案）＝ 每个成员**先按自己那一组**归一成组内相对分，再按**成员金数占比**
  加权；队伍总金 0 时退回等权平均。
  恒等式：**队级 ③ = 成员们在总榜上泛用性分的成本加权平均**。
* 归一是 **min-max**，但**不再是「榜内」**：角色级用上面那两把组尺子，队级仍是**池内**
  min-max（成员那一层已经是绝对刻度，队级再铺满 0~100 只是让权重使上力）。
* 泛用性权重**也适用于补金推荐**（用户 2026-10-13 第 3 条），即三键在方案里一并归一。
* ⚠️ **已知特性**（不是回归）：两组 min-max 之后**均值持平**（实测榜上 261 个
  `角色|E档` 去重后，低档组组内相对分均值 10.1、E6 组 10.7），但**中位数仍差一截**
  （4.6 vs 2.7）—— E6 那把尺子的上界被单个角色（知更鸟 E6，7.22）独自撑高，
  min-max 对离群值敏感。要改成对离群值免疫的尺子（分位 / 秩次）是**另一个决策**，
  用户拍板后再动。

| --- | --- |

| 配队行 | `E{档} [光锥图标] 光锥名 S{n} ·` **`成本 {N} 金`** ✅ v4.6.114 由「整包 N 金」改 · `角色得分 +{分}` |

| 条数 | 最多 30 条，其余写「另有 N 个配队未列出（该角色共 M 个）」 |
| 每行的逐关卡 | 关卡名 + 成绩/系数 + 该关队伍卡片（头像 + 名字 + E 档 + 光锥）+ 来源视频图标 |
| 脚注 | **不出现**「满分 / 达标 / 及格」这类自造词；**不出现** `÷`（除法写 `/`）；每条 ≤60 字 |

⚠️ 性价比来源那张表里还有一条脚注：
`整包 = 角色 + 星魂档 + 光锥（含叠影）；整包自身 N 金不进公式。`
它是**术语定义**（说明「整包」是什么），不是成本标签，**本轮不动**（见 §9 待确认）。

### 6.3 「原始量 → 得分 → 贡献」这条链（每个分项各自不同）

分项表就四步：**原始量**（自己量纲的累计值）→ **得分**（换到 0~100）→ **权重**（抽卡权重）
→ **贡献**（`得分 × 权重`），三行贡献相加 = 角色得分。三个分项的换算方式**不一样**，
这正是必须把「原始量」摆出来、并写出榜内区间的原因（否则读者按 min-max 去验算强度，
永远对不上）：

| 分项 | 原始量是什么 | 量纲 | 原始量 → 得分 |
| --- | --- | --- | --- |
| **强度** | `strengthTotal` = Σ(关卡权重 × 该关强度) / Σ(**全部**副本权重)，缺副本按 0。该关强度按 §4.1 两档规则逐关算 | 0~100 的分（绝对刻度） | **不 min-max**：得分 = 包络 / 天花板之后的那个原始量。顶格档 = `100 × 本期最省金 ÷ 本队金数`，非顶格档封顶 90。所以得分**常等于**原始量（v4.6.116 起不再有 `+ 5 × 第二维` 那一档折算） |
| **性价比** | `total` = Σ(关卡权重 × 该关的整包分)，即老口径「含金数项的整包分」 | 几百~上千的分数（与强度不是一个量纲） | 得分 = `100 × (原始量 − 榜内最小) / (榜内最大 − 榜内最小)`，区间取**全榜**（实测 0.23 ~ 644.18） |
| **泛用性** | 加权的**不同队友数**（副本内按版本权重、跨副本按关卡权重，缺投稿版本计 0） | **个数**（小数，实测缇宝 1.88 个） | min-max，但尺子**按组各一把**（2026-10-17 第 1 条）：低档组（E0/E1/E2 三档平均）与 E6 组各自 `lo/hi`。为 0 的两种来源：① 组内最小；② 该角色本身是「不用抽就有」的那批 → **既不攒自己的集合、也不当别人的队友**（实测希儿 / 镜流 / 银狼 = 0） |

📌 一句话：**原始量是"算分之前那个数"，得分是"换算到 0~100 之后的数"，贡献是"这个分项最终给角色得分加了多少"**。
界面上那一列下还会写 `（榜内 0.2 ~ 644.2）` 或 `（绝对刻度 0~100）`，就是为了让读者能自己验算。

（上表那三个分项名在**详情窗口**里显示为「角色强度 / 角色性价比 / 角色泛用性」，
在**总榜筛选器上方**那三个输入框里仍显示为「强度 / 性价比 / 泛用性」—— 见 §3.2 那条 ⚠️。）

### 6.4 权重栏与隐金设置的位置（✅ v4.6.115，用户 2026-10-17 第 1 条）

## 7. 文案总则（有源码级 / 全窗口判据）

1. 界面**不许**出现「满分 / 达标 / 及格」（源码级判据，`herta-test`；注释里可留作历史说明）。
2. 界面**不许**出现 `÷`（`check-advice-layout` 全窗口判据）；除法写 `/`。
3. 数值统一走既有 helper（`goldText()` / `factorText()` / `packScoreText()`），不许在别处
   用 `textContent` 拼一遍（否则会出现「有的数字白、有的灰」）。
4. 来源表里的数字必须**可验算**：读者按表里的说明能算出榜上那个分。
5. 「配队」不写「配装」；「成本 N 金」不写「整包 N 金」。
