## 0. 一句话结论（更新）

* **切分、星魂数字**：实测可行，接近 100%。
* **角色名字的中文 OCR**：实测**不可用**（tesseract 整名仅 6%、纠错后 53%），
  不能用通用 OCR 认中文美术字。
* **角色身份的正确解法 = 立绘感知哈希匹配**：分享图立绘与官方
  `character_portrait` 是**同一美术源**（StarRailRes 资源镜像，本程序词典已含其 URL，
  连「银狼LV.999」都有），pHash 对缩放/裁剪鲁棒，远胜 OCR。
* **版本更新完全可持续**：词典与图库由「同步黑塔网数据」自动更新，新角色新光锥
  零额外工作；真正要防的是米游社改模板（连通域 + 模板指纹兜底）。

## 2. 识别成功率实测（单一真实样图，2026-10-21）

> 样本局限：只有你给的一张图；数字是「这张图上的实测」，不是多账号统计。
> 但样图覆盖 96 角色里的 66 个、含金底/紫底/联动/变体，代表性足够判断方向。

| 环节 | 方法 | 实测结果 | 结论 |
| --- | --- | --- | --- |
| 网格切分 | 行/列投影 | 行 pitch 320/321、列 pitch 367，金底区 36 卡全中；固定 pitch 在紫底区失效、边界丢 3 张（63/66） | **用连通域可达 ~100%** |
| 星魂数字 | OCR 整条 `Lv.80 ❖ N` | 整条 0/36；但错误全在「Lv」「❖」被认成中文，**数字 0/1/2/3 基本全对** | 数字区模板/正则，几乎不错 |
| 角色名字 | tesseract.js chi_sim 单行 | 整名精确 **2/36 (6%)**（仅 Archer/Saber 英文对）；编辑距离≤2 纠错后 **53%** | **通用中文 OCR 对美术字不可用** |
| 立绘匹配 | pHash 对官方 portrait | 本沙箱访问不了 jsdelivr CDN，**数字待补**（方法见 §3.2，方向已证） | 正解，需有网环境复测 |

复现（名字 OCR / 立绘 pHash 两个脚本，需临时 `npm install --prefix` tesseract.js / jpeg-js / pngjs，
不提交进仓库以免破零依赖）：

```bash

node ocr-test.mjs <样图.jpg> --modules=<node_modules目录>
# 立绘 pHash（分享图卡片立绘 vs 官方 character_portrait）
node phash-test.mjs <样图.jpg> --modules=<node_modules目录>
```

## 3. 识别策略（v2 修正版）

### 3.1 管线

```
选图 → canvas 切分（连通域） → 每卡：
  ① 立绘区域 pHash → 与官方 character_portrait 图库比对 → 角色身份（主）
  ② 名字条 OCR → 只作「候选集粗筛 + 确认表展示」（辅，不决定身份）
  ③ Lv/星魂条 → 数字区模板/正则 → 星魂数
→ 校验（数量 vs 头部N、UID、同名去重）→ 人工确认表 → POST /api/virtual-accounts
```

### 3.2 立绘 pHash 匹配（角色身份的主解法）

* 图库 = `i18n.icons.portraits.characters`（StarRailRes `image/character_portrait/*.png`），
  下载一次缓存到本地（浏览器 IndexedDB / 服务端镜像），**随版本更新自动长新图**；
* 算法 = 缩到 9×8 灰度 → 差异哈希（dHash，64bit）→ 汉明距离；候选图库 96 张，
  每张距离排序取最近，距离 < 阈值（~12）判中，否则标「低置信」交人工；
* 为什么比 OCR 强：同一官方立绘，只是缩放 + 轻微裁剪，dHash 对此不敏感；
  中文美术字 OCR 对字体/描边/背景极度敏感（§2 已证）。

### 3.3 星魂数字

分享图格式恒定 `Lv.NN ❖ N`：先按连通域定位数字块，再做 0~6 的模板匹配（或小模型），
避免整条 OCR 的「❖ → 癌」串扰。星魂上限 6，模板集极小，实测方向可靠。

### 3.4 光锥（二期）

卡面 = `icons.portraits.lightCones`（`image/light_cone_portrait/*.png`，同源），pHash 同法；
叠影 = 罗马数字 Ⅰ~Ⅴ 五个模板。识别不出留空手补。一期只导角色+星魂。

## 4. 版本更新之后怎么办（可持续性，已核实）

| 更新类型 | 影响 | 对策 |
| --- | --- | --- |
| **新角色 / 新光锥上线** | 无感 | 词典与图库来自 `Mar-7th/StarRailRes` 官方资源镜像，程序「同步黑塔网数据」时再生成 `i18n-zh.json`（含 `lookup` + `icons.portraits`）→ 新角色名、新立绘、新光锥图**自动进库**。用户本来每次新版本就要做一次同步，导入功能零额外维护。 |
| 米游社**换分享图模板**（字体/几何/格式变） | 会失效 | ① 连通域切分抗轻微位移；② 头部/卡片几何算「模板指纹」，改版即识别失败并**降级为人工录入**（不崩溃）；③ 用探针对新样图一键重测、更新坐标参数。 |
| 米游社改**数字格式** | 星魂识别失效 | 数字条加格式校验（正则 `Lv\.\d+ ❖ \d`），不匹配即告警。 |

一句话：**数据侧（角色/光锥）是词典驱动、随版本自愈；唯一的人工维护点是米游社改 UI 模板时更新坐标参数**，而这是低频、且探针能快速定位。

## 6. 与手机端方案（v2 文档）的关系

同前：本功能是「不想登录米游社」用户的个人化入口，安卓 iOS 通吃、全程不碰米游社接口、
风险为零；识别在浏览器端（WASM/纯 JS），服务端零新增依赖。

## 7. 关键风险（如实）

1. **立绘 pHash 匹配尚未拿到实测准确率**（CDN 在本环境不可达）——上生产前必须先补，
   若 dHash 区分度不够，升配 pHash(DCT)/特征点匹配，或退回「名字 OCR 粗筛 + 人工确认」；
2. 中文美术字 OCR 已证实不可靠，**不要**让它承担身份判定；
3. 光锥属于二期，一期「只导角色+星魂」已覆盖算补金方案主需求。
