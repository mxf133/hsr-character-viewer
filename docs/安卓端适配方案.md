# 手机端方案 v2：独立运行（安卓 / iOS）+ 米游社数据风险与替代（2026-10-21）

> 分支 `feat/android-client`。**v2**（用户澄清需求后重写）回答两个问题：
> ① 这个程序能否在手机上**独立运行**（不依赖 PC），安卓和苹果分别怎么办；
> ② 米游社数据获取有风险的话，有什么别的办法。
> v1（局域网 / 远程访问 / PWA）的结论仍然成立、仍是 iOS 的主要出路，保留在 §6。

---

## 1. 结论先行

| 问题 | 答案 |
| --- | --- |
| 安卓能独立运行吗？ | **能**。Termux 直接跑（今天就能用，零改造）；或用 nodejs-mobile 打包 APK（体验最好，工程量大）。 |
| iPhone 能独立运行吗？ | **普通用户不能**。iPhone 上没有真 Node（iSH 跑 V8 直接 illegal instruction；a-Shell 是 JavaScriptCore，没有 Node）。现实解 = 远程服务端 + Safari/PWA，或「快捷指令抓数据 → 导入」。 |
| 米游社数据有别的来源吗？ | **个人数据没有**。角色快照、五个副本的挑战记录只有米游社记录接口一个来源（需登录 cookie）。能替代的是「非个人数据」：强度榜 / 配队 / 上场率用 theherta 数据集（已在用，不登录即可）；个人角色可手填虚拟账号（零请求）。 |
| 风险到底有多大？ | 官方公告打击的是**游戏内的自动化脚本 / 作弊工具**；查询类工具的实际后果是风控验证码（1034）/ 接口临时限流，封号案例罕见，但条款上不被允许、账号理论上担责。程序已有的降险设计（默认不联网、显式刷新、限流、cookie 只存本机加密）必须保住。 |

## 2. 个人数据到底从哪来（代码盘点）

| 功能 | 数据来源 | 是否需要米游社登录 |
| --- | --- | --- |
| 角色强度总榜、配队、上场率、抽卡方案池 | theherta.com 公开数据集（`theherta/*.json`，随仓库分发） | **否**（不登录就能用，README 也这么承诺） |
| 标出「已有」、按你的角色池算补金 | 角色快照：`getFullSnapshot`（`src/mihoyo/starrail.js`） | **是**（cookie + DS 签名 + 设备指纹） |
| 五副本战绩 → 强度分 / 行动值 | `getChallenge` / `getChallengeStory` / `getChallengeBoss` / `getPeakChallenge` 等记录接口 | **是** |
| 不登录也要的个人推荐 | 「虚拟账号」手填角色 / 光锥 / 命座（`virtual-accounts.js`，界面已支持） | **否**（完全零请求） |
| 手动登录 | 扫码（服务端代理轮询）或直接粘贴 cookie（`/api/login/cookie`，已支持） | 是 |

结论：**「拿米游社数据」只服务于个人化功能**；浏览与方案池不依赖它。

## 3. 安卓：独立运行的两条路

### 3.1 Termux 直接跑（推荐，零代码改造）

服务端代码是零依赖 Node ESM，非 Windows 分支齐全（凭证走 AES-256-GCM、watchdog 走 POSIX 探活），Termux 可直接运行：

```
pkg install nodejs-lts git
git clone <本仓库> && cd 抽卡推荐计算器
export DSH_HSR_CREDENTIAL_KEY=<自己编的长随机串>   # 非 Windows 必设，否则拒绝持久化凭证
node bin/serve.mjs --host 127.0.0.1
# 浏览器打开 http://127.0.0.1:8360/
```

* 注意点：① Android 的 phantom process killer 会杀后台进程（`signal 9`）—— 要么关掉
  （开发者选项 / adb），要么用 `termux-services` 把服务挂成守护 + 电池白名单；
  ② 数据集（`theherta/`）随 git 一起拉，首次更新走界面里的「同步黑塔网数据」。
* 适合：愿意折腾命令行的用户。**这是今天就能交付的形态。**

### 3.2 nodejs-mobile 打包 APK（体验最好，工程量大）

* Janea Systems 已停止维护，但社区 fork（`github.com/nodejs-mobile` org）仍在活跃
  （2025-11 还在更新，Node 基线 18.20.4，部分 fork 已到 v24；Android 构建支持 16KB 页对齐）。
* 形态：Capacitor（或 React Native）壳 + nodejs-mobile 插件跑 `bin/serve.mjs` 的服务端 +
  WebView 加载 `http://127.0.0.1:<port>/`。
* 需要的适配（都是可控的）：凭证加密强制走 AES 分支（传 `DSH_HSR_CREDENTIAL_KEY`）；
  `data/`、`theherta/icons` 指到 App 沙盒目录；去掉 start.bat / watchdog 等 Windows 件；
  图标镜像随包或首启下载。
* 适合：想给「不懂命令行的普通玩家」分发时。**iOS 侧同一框架理论可行，但分发见 §4。**

### 3.3 不推荐

* 云容器类 App（如 Cosyra 之类，$20/月租个云里跑 Node）：能跑但完全失去「本地独立」的意义，
  凭证还过第三方 —— 不如直接用 §6 的远程服务端方案。

## 4. iPhone：为什么不能独立运行，现实解是什么

### 4.1 技术事实（2026-10 核实）

* **iSH**（x86 Linux 模拟器）：能 `apk add nodejs`，但运行即崩 —— iSH 不实现 V8 JIT 依赖的
  SSE2 指令（长期未解的 issue），且纯模拟本身就慢。**此路不通。**
* **a-Shell**：内置 JavaScriptCore，没有 node 二进制、没有 npm、没有 Node API，2021 年起
  的功能请求至今未实现。**此路不通。**
* **nodejs-mobile 嵌入自家 App**：技术上可行（有 iOS framework 构建），但**分发给普通用户
  无解** —— 不越狱不能侧载；App Store 上架过不了审（不允许 JIT / 执行下载代码，且
  「代抓米游社数据」的应用本身就是审核雷区）。**只适合自用（自有开发者账号自签）。**
* 结论：**iPhone 上「程序完全独立运行」对普通用户不可行**，这不是本项目的问题，是平台限制。

### 4.2 iOS 现实解（按推荐排序）

1. **远程服务端 + Safari / PWA**（v1 §6 的路线 A/B）：服务端跑在 PC / 家庭 NAS /
   Termux 安卓机上，iPhone 浏览器访问（局域网或 Tailscale）。体验上是「iPhone 版」的唯一
   正路，PWA 加到主屏幕后接近原生观感。
2. **iOS 快捷指令路线**（进阶，需要新增一个导入接口）：快捷指令可以直接发 HTTP 请求并支持
   MD5 哈希 —— 理论上可以在 iPhone 上**自己算 DS 签名**请求米游社记录接口，把 JSON 存到
   「文件」，再粘给本程序的网页导入。工程量：新增 `/api/import/snapshot` 与
   `/api/import/records` 两个只吃 JSON 的接口（中等）。收益：iPhone 用户无需任何服务端也能
   个人化。⚠️ 本质仍是「你的 cookie 请求米游社」，风险定级不变（§5）。
3. **手动 cookie 粘贴到远程服务端**（现状已支持）：iPhone 上打开米游社网页版复制 cookie，
   粘到远程跑的本程序里。
4. **纯手动**：虚拟账号手填，零米游社请求。

## 5. 米游社数据：风险定级与替代方案

### 5.1 风险定级（基于公开信息，2026-10 核实）

* 米游社官方公告（70386618 等）打击的对象是**鼠标宏、自动化脚本等危害游戏公平的第三方工具**
  —— 即游戏内行为作弊；**查询战绩 / 展示数据类工具不在打击名单里**。
* 社区现实：胡桃工具箱（Snap.Hutao）等查询类工具大规模使用多年；常见「后果」是触发风控
  （1034 要过验证码 / 接口临时拒绝），**封号案例罕见**，但用户协议层面不被允许，
  账号理论上担责 —— 这一点必须如实告知用户。
* 本程序的请求特征天然低危：只读接口、**默认完全不联网**（有本地数据时刷新不回源）、
  显式刷新 + 最小间隔限流、扫码登录走官方二维码流程。与「爬虫式高频抓取」完全两回事。

### 5.2 降险手段（已有 + 可加强）

| 手段 | 状态 |
| --- | --- |
| 有本地数据时读取一律不联网，只有显式刷新才回源 | ✅ 已实现（`cache-policy.js` 回源闸门，用户 2026-10 明确要求过） |
| 回源最小间隔限流 | ✅ 已实现 |
| cookie 只存本机（加密）、不上传任何第三方 | ✅ 已实现（AES / DPAPI 凭证库） |
| 设备指纹 7 天复用，不反复申请 | ✅ 已实现（`ensureFingerprint`） |
| 「用完即删」模式：登录会话不持久化，关服务即丢 | 可加强（小改动：启动参数跳过凭证落盘） |
| 不支持也永远不加入：自动签到、自动游戏内操作 | 红线（会从「查询」变成「脚本」，风险质变） |

### 5.3 替代方案（按「你想替代什么」分）

| 你要什么 | 替代方案 | 风险 | 代价 |
| --- | --- | --- | --- |
| 强度榜 / 配队 / 上场率 / 方案池（非个人数据） | **theherta 数据集（已在用）** —— 不登录就能用 | 零 | 无 |
| 深境 / 副本统计参考 | Snap.Hutao 公开统计 API（UIGF 生态） | 零（公开汇总） | 数据是上传制汇总，粒度粗 |
| 个人角色面板（命座 / 光锥） | **虚拟账号手填**（已支持）；或 iOS 快捷指令 / 米游社截图 OCR（工程大、易错） | 零 | 手动维护 |
| 个人五副本战绩 | **无替代来源**（第三方统计站只有汇总，没有个人记录）—— 只能米游社接口，或将来支持「从米游社 App 战绩页手动录入」 | 见 §5.1 | 需登录 |
| 抽卡记录（本程序当前不需要；若未来要） | **手动导出 UIGF / Snap.Hutao JSON 导入**（零风险）；不要用「输 URL 自动拉取」的方案（自动拉取历史上有风控案例） | 手动导出 = 零 | 每期手动导 |

## 6. v1 结论（仍然成立）：手机怎么「用上」这个程序

* 路线 A **局域网直连**（首选，改造量≈0）：PC 跑 `HOST=0.0.0.0` + `DSH_HSR_TOKEN`，
  手机浏览器开 `http://<内网IP>:8360/#token=…`（前端 `access.js` 已支持读 hash 后抹除）。
* 路线 B **异地访问**：Tailscale（推荐，端到端加密零改造）> frp / Cloudflare Tunnel
  （必须配 HTTPS）。红线：明文 HTTP 出公网不可接受。
* 路线 E **PWA 增强**：manifest + SW 静态壳（不缓存 `/api/*`），叠加在 A/B 上。
* 待办（v1 遗留）：`bin/serve.mjs --lan`（自动令牌 + 打印内网地址 + 终端二维码）、
  README「手机访问」章节、320px 顶栏收窄（探针实测唯一溢出点）。

## 7. 推荐组合（按用户画像）

| 用户 | 方案 |
| --- | --- |
| 安卓 + 愿意折腾 | Termux 独立运行（§3.1）—— 真正的「手机独立」 |
| 安卓 + 普通玩家 | PC / NAS 跑服务端 + 局域网 / Tailscale（§6）；若决定长期投入，再评估 APK 打包（§3.2） |
| iPhone | 远程服务端 + Safari/PWA（§4.2-1）；极客可等「快捷指令导入」（§4.2-2） |
| 不想担米游社任何风险 | 不登录：总榜 / 配队 / 上场率照用；要个人推荐 → 虚拟账号手填 |
| 明确不做 | iOS 上架、越狱侧载、公网明文 HTTP、自动签到 / 游戏内自动化 |
