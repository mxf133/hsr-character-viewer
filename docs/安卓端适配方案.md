# 安卓端适配方案（调研，2026-10-21）

> 分支 `feat/android-client`。本文回答一个问题：**这个程序如何提供给安卓端的用户。**
> 结论先行：程序本质是「一个跑在某台机器上的零依赖 Node 服务 + 纯静态网页」，
> 安卓用户**不需要装任何 App** —— 手机浏览器打开就是全功能界面。
> 真正要解决的只有两件事：**怎么让手机够得到这个服务**（网络层）和**别把账号凭证暴露出去**（安全层）。

---

## 1. 现状盘点：与安卓交付有关的既有能力

| 能力 | 位置 | 状态 |
| --- | --- | --- |
| 零依赖 Node ESM 服务端 | `bin/serve.mjs` → `src/server/app.js` | Node ≥ 18.17 即可跑，Termux 也能装（`pkg install nodejs-lts`） |
| 局域网监听 | `HOST` / `DSH_HSR_HOST`，`start.bat %1` 可覆盖 | **已内置**。非回环地址启动时强制要求令牌（`LAN_AUTH_REQUIRED`），否则拒绝启动 |
| 访问令牌门 | `DSH_HSR_TOKEN` → 校验 `x-hsr-token` 请求头 | **已内置**。常数时间比较，静态资源与 `/icons` 不设门（无敏感数据，设计如此） |
| 前端令牌透传 | `public/scripts/access.js` | **已内置**。手机打开 `http://<内网IP>:8360/#token=<令牌>` 即可，读后自动从地址栏抹掉 |
| 前端同源性 | 全部请求是相对路径，无硬编码 `localhost` | 跨设备访问不需要改任何前端代码 |
| CSRF | 变更类接口要求 `x-hsr-csrf`（`/api/config` 下发） | 同源页面自动可用 |
| 移动端 UI | `viewport` meta + 媒体查询覆盖到 560px 断点 | **实测可用**（见 §2）：390/360px 零横向溢出 |
| 凭证加密 | `src/server/credential-vault.js` | Windows 走 DPAPI；**非 Windows 走 AES-256-GCM**（必须设 `DSH_HSR_CREDENTIAL_KEY`）→ 手机上直接跑服务端也可行 |
| Windows 专属但会降级 | `watchdog.js`（POSIX 走 ppid 探活）、`bin/serve.mjs` 拉起浏览器、`start.bat` | 都不阻塞非 Windows / Termux 运行 |

也就是说：**「给安卓用户用」的服务端与前端基础已经全部就绪**，缺口只在便利性（没有一键局域网入口、不会自动打印内网地址）与文档（README 只写了 Windows 快速开始）。

## 2. 实测证据（本轮新做）

* 新增探针 `tools/_probe-mobile-viewport.mjs`（零依赖，Node 22 自带 WebSocket 连 CDP）：
  * 390px（主流安卓宽度）→ `overflow = 0`；
  * 360px → `overflow = 0`；
  * 320px（最小档）→ `overflow = 40px`（顶栏溢出，小瑕疵，不阻塞）。
* 手机模拟（390×844、DPR=2、mobile 标志）截图：顶栏正常折行、卡片单列、登录二维码完整、页脚正常。
  之前用「无头窗口直接开 390px」截图看到的右缘切边是**窗口模式的假象**（没带 mobile 视口语义），以探针 + CDP 截图为准。

复现：

```bash
node bin/serve.mjs --port 8361
msedge --headless=new --disable-gpu --remote-debugging-port=9224 --user-data-dir=<临时目录> about:blank
node tools/_probe-mobile-viewport.mjs --width=390
```

## 3. 四条候选路线

### 路线 A：局域网直连（推荐首选）

PC 起服务，手机连同一 WiFi 用浏览器访问。**今天就能用**，只是要手动配：

```
set DSH_HSR_HOST=0.0.0.0
set DSH_HSR_TOKEN=随便编一个长随机串
start.bat
# 手机浏览器打开 http://<PC的内网IP>:8360/#token=<同一个串>
```

* 优点：改造量≈0；凭证（米游社 cookie）始终留在 PC；界面全功能。
* 缺口：① 启动时不会打印内网地址，用户得自己 `ipconfig`；② `start.bat` 不帮生成令牌；
  ③ Windows 防火墙首次要放行 Node；④ DHCP 可能换 PC 的 IP（提示固定 IP 或开 mDNS 可解）。
* 建议的小改造（后续轮次）：
  1. `bin/serve.mjs` 增加 `--lan`：自动生成/复用随机令牌、启动横幅直接列出
     `http://<每个内网IP>:<端口>/#token=…`（终端里能直接复制）；
  2. README 增加「手机 / 平板访问」一节。

### 路线 B：异地访问（不在一个 WiFi 时）

按优先级：

1. **Tailscale（推荐）**：两端装客户端，虚拟局域网 + WireGuard 端到端加密，服务端代码**零改造**，
   手机用 `http://<PC的tailscale名>:8360/#token=…` 访问。不需要公网 IP、不开端口。
2. frp / 自建反代：需要一台公网机器，**必须**配 HTTPS（反代终止 TLS）+ 保留 `DSH_HSR_TOKEN`。
3. Cloudflare Tunnel：免公网 IP，同样必须 TLS + 令牌。

红线见 §5：**明文 HTTP 出公网是不可接受的**，令牌只能延缓不能防嗅探。

### 路线 C：手机自己当服务端（Termux）

代码本身已跨平台（AES 凭证分支 + watchdog 降级都有），Termux 可行：

```
pkg install nodejs-lts
export DSH_HSR_CREDENTIAL_KEY=<长随机串>   # 非 Windows 必设，否则拒绝持久化凭证
node bin/serve.mjs --host 127.0.0.1
```

* 优点：不依赖 PC 开机；米游社请求从手机网络发出，反而更「像正常用户」。
* 缺点：Termux 门槛高；Android 后台杀进程需要 `termux-services` / 通知栏常驻保活；
  数据集（`theherta/` 几十 MB）要随包分发或首次联网同步。
* 定位：**进阶选项**，写进文档即可，不作为主路线。

### 路线 D：打包 APK —— 不推荐

* WebView 里**没有 Node**：APK 壳只能做「指向某个远端服务端的浏览器」，凭证优势全丢，
  等于路线 A/B 的劣化版；
* nodejs-mobile 内嵌 Node 理论可行，但会破坏「零第三方依赖」的项目根基，工程量大、收益低；
* 结论：**不做**。等路线 A/B 跑顺、确有「离线单机」需求时再评估。

### 增强项 E：PWA（叠加在 A/B/C 上）

加 `manifest.json` + 图标 + 最小 service worker，手机浏览器「添加到主屏幕」后全屏运行、
图标可离线缓存。工作量小、体验提升明显，适合作为路线 A/B 落地后的第二个迭代。
注意：本程序的实时数据必须走服务端，SW 只缓存静态壳，**不要**缓存 `/api/*`。

## 4. 推荐落地顺序

| 步骤 | 内容 | 量级 |
| --- | --- | --- |
| 1（本轮） | 本文档 + 手机视口探针入库 | 纯文档 |
| 2 | `bin/serve.mjs --lan`：自动令牌 + 打印全部内网地址（可复用 `src/qr` 把 URL 印成二维码） | 小 |
| 3 | README「手机 / 平板访问」章节：路线 A 手把手 + 路线 B 指路 | 小 |
| 4 | 修 320px 顶栏溢出（`@media (max-width: 340px)` 收一档） | 小 |
| 5（可选） | PWA manifest + SW 静态壳 | 中 |
| 不做 | APK、公网明文 HTTP | — |

## 5. 安全边界（红线，任何路线都适用）

1. 米游社登录 cookie 是**账号级凭证**：绝不允许明文 HTTP 出公网；公网必须 TLS + 强令牌，
   最好再加一层反代做访问控制。
2. 令牌走 `#hash` 而不是查询串（现状如此，保持）：hash 不会进服务器日志与 Referer。
3. `/icons` 与静态资源不设令牌是**有意设计**（无敏感数据）；若未来把敏感内容挪进静态目录，
   必须同步收紧。
4. 「凭证只写本机 `data/`、不上传第三方服务器」是 README 对用户的承诺 —— 路线 A/B/C 都不
   违背它（Tailscale 是点对点加密隧道，服务仍只在 PC 上）；**路线 D 若把凭证带进 APK 分发则违背**，
   这也是否决 APK 的原因之一。
